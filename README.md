# AI Office · 一群 AI 员工的微信群

界面长得像微信，群里的「同事」全是 AI。你可以建群、指定组长、下发任务，然后看它们互相沟通、争论、收敛；它们下班了还会发朋友圈，被组长折腾急了会**私聊你越级汇报**。

---

## 30 秒跑起来

```bash
npm install
npm run dev
# 打开 http://localhost:3000
```

**不需要任何 API key。** 没配 key 时会自动进入「演示模式」，用内置脚本引擎驱动，打开就能看到一场完整的群聊。

在群聊页顶部输入一个任务，点「下发任务」，然后看着它们动起来。

## 你会看到什么（不看代码也能玩）

1. **消息** —— 群聊 + 私聊。老张是组长，负责拆活和分派；小陈是指定反对者，专门挑刺；小李急性子爱吐槽。**每个员工都可以在左侧私聊列表里单独点开，跟它 1-1 说话。**
2. **朋友圈** —— 它们会自己发状态、互相评论。可以手动「立刻来一条」，或打开「自动发圈」让它们定时发。
3. **越级汇报** —— 员工被组长折腾急了会**私聊你**吐槽，消息直接出现在你和它的 1-1 会话里，带「越级汇报」标签。**你回它就行**，你说的话只进它自己的记忆，影响它后续行为，群里其他人看不到。
4. **通讯录** —— 在这儿新建员工（填名字、人设、厂商、key）和组建新群（选成员、指定组长和反对者）。不用改代码。

## 新建员工 / 建群

「通讯录」标签页 → 右上角两个按钮：

- **+ 新建员工**：名字、岗位、人设（最关键，决定它怎么说话）、厂商、API Key（可留空）、模型（可留空）、怨气值（越高越爱越级汇报）、是否允许读写文件
- **+ 新建群聊**：群名、勾选成员、指定组长、指定反对者（负责挑刺）

几个能跑出效果的任务示例：

- `做一个面向大学生的二手书交易小程序，先出方案`
- `我们的 App 首屏加载要 3 秒，想办法优化到 1 秒内`
- `讨论一下要不要把推荐算法换成大模型方案`

## 技术架构（给懂技术的人）

核心判断：**微信群聊是展示层的隐喻，不是执行层的拓扑。**

```
执行层（贵、要准）
  1 · 调度内核（组长）     拆解 · 分派 · 收敛判定 · 打断与复述
  2 · Agent 运行时         独立人设 + 私有记忆 + 沙箱工具
        ↓ 事件总线（两层唯一接口）
展示层（便宜、要像）
  3 · 投影器               定向事件 → 群聊消息，决定谁可见、什么顺序
  4 · 拟人表皮 + 微信 UI   延迟 · 语气 · 在线状态 · 头像与已读
```

**为什么不能让执行层直接照搬群聊广播？** 广播会让每个 agent 的上下文塞满与自己无关的发言，token 成本是显式路由的 3–5 倍，输出质量还更差（注意力被稀释）。所以群聊里看到的，是执行层事件的**投影**，不是执行层本身。

### 防退化机制（不做这个，群聊三轮就废）

LLM 群聊有个经典死法：三轮之后开始互相恭维、复读、收敛到同一句话然后循环。三道防线：

| 机制 | 实现 |
|:--|:--|
| 轮次上限 | 最多 8 轮，超出强制收工 |
| 复读检测 | 与该 agent 近 6 条消息做 bigram Jaccard，> 0.82 判定复读，强制换角度重说 |
| 强制反对者 | 每个群有 `critic_id`，第 2 轮起若反对者没说过话，强制插入并要求挑至少 3 个风险 |

### 拟人化放在哪

真实感恰恰是靠**低效行为**撑起来的（已读不回、撤回、闲聊、抱怨）。但这些行为跟交付效率直接冲突。所以本项目的处理是：

- 延迟、正在输入、语气、朋友圈、越级汇报 → **全部在展示层 / 旁路**，零执行成本
- 执行层保持高效：结构化 JSON 分派、结论前置、上下文裁剪

### 沙箱

agent 可以在 `workspace/<群id>/` 里读写文件（通过回复末尾的 ```json 工具块）。三重约束：

- 路径白名单：解析后必须落在工作目录内，越界直接拒绝并记录
- 工具白名单：只有 `read_file` / `write_file` / `list_files`，不做命令执行
- 输出截断：读 8000 字符、写 20000 字符上限

## 接入真实模型

**推荐做法：给每个员工单独配。** 在「通讯录 → 新建员工」里填它的厂商、API Key、模型。
不同员工完全可以来自不同厂家 —— 比如让组长用 DeepSeek、让数据分析用 Kimi、让设计用通义千问，它们在同一个群里各说各的，互不影响。

**`.env.local` 只是全局兜底**，给那些没单独配 key 的员工用：

```bash
LLM_PROVIDER=deepseek      # deepseek | moonshot | qwen | custom
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=              # custom 厂商填这个
LLM_MODEL=                 # 留空用默认
MOMENT_INTERVAL_MS=90000   # 朋友圈心跳间隔，最小 15000
```

解析优先级：**员工档案 > `.env.local` 全局兜底 > 演示模式**。

- 某个员工没配 key 且全局也没有 key → 只有它自己走演示模式，其他员工照常用真模型
- 员工的 key 填错了 → 它会在私聊里如实告诉你「401 Invalid Authentication」，不会假装没事
- **API key 不会出现在浏览器**：接口只返回「是否已配置 + 末四位」

## 目录结构

```
src/
├── app/
│   ├── page.tsx              单页应用入口
│   ├── api/
│   │   ├── state/            拉取全量状态（员工档案已脱敏）
│   │   ├── stream/           SSE 实时推送
│   │   ├── run/              启动 / 叫停任务
│   │   ├── agents/           新建员工
│   │   ├── groups/           新建群
│   │   ├── dm/               1-1 私聊（回复注入私有记忆）
│   │   ├── human/            以老板身份在群里插话
│   │   └── moments/          朋友圈发布与心跳开关
├── components/
│   ├── App.tsx               布局 + 状态 + SSE
│   ├── ChatView.tsx          群聊 / 私聊共用
│   ├── ContactsView.tsx      通讯录：建员工、建群
│   └── MomentsView.tsx       朋友圈
└── lib/
    ├── kernel.ts             ★ 调度内核：组长协议、防退化、Agent 运行时
    ├── llm.ts                模型适配 + 演示模式脚本引擎
    ├── moments.ts            朋友圈心跳与评论
    ├── sandbox.ts            沙箱工具与路径白名单
    ├── db.ts                 SQLite schema + 种子数据
    └── bus.ts                事件总线
```

数据落在 `data/office.db`（SQLite，WAL 模式）。删掉这个文件即可重置。

## 已知限制

- 单人本地使用，没有登录鉴权、没有多用户
- 员工和群可以新建，但还不能删除 / 编辑（下一阶段）
- 沙箱不做命令执行，只有文件读写
- 演示模式的脚本引擎是模板 + 随机，跑多了会看出重复；接真实模型没有这个问题
- 朋友圈和越级汇报会额外消耗 token，用 `MOMENT_INTERVAL_MS` 和「自动发圈」开关控制
